## 0. 一句话结论

把「基因工程」做成一张**以操作为骨架、以实体为节点、以档案为落点**的知识图：

- 主线五站：**切 → 接 → 转 → 检 → 养**；
- 图上节点分四类：**操作站、判定点、实体锚点、概念/边界**；
- 每个实体有自己的档案页，档案页不复述流程图，只回答「它是什么、在哪一步、怎么起作用、边界在哪」；
- 数据层只存事实与关系，版面坐标单独存放；页面只做「数据 → 版面 → 交互」的映射。

## 1. 生化项目的分层调研

### 1.1 目录与职责

| 层 | 生化项目中的位置 | 放什么 | 谁在用 |
|---|---|---|---|
| 内容数据 | `src/data/<pathway>/<name>.json`、根目录 `glycolysis.json`、`tca.json` | 实体清单、步骤、反应式、酶、辅因子、生理意义、器官差异、可选字段 | 各通路页、`stepIndex.ts`、气泡 |
| 版面数据 | 同目录 `skeleton.json` | 节点 id、坐标、泳道、支路、连线与 `stepId` 绑定 | 挂图 SVG、首页 |
| 导航索引 | `src/data/homeMap.ts`、`pathways.ts` | 通路 id、显示名、路由、PLATE 编号、步数 | 首页、导航、跨页 |
| 档案数据 | `src/data/moleculeProfiles.ts` | 182 条物质档案：判断句标题、分类、结构、四段正文、考点、出处 | `/molecule/:id` |
| 目录数据 | `src/data/substances.ts` | 六类物质目录，条目可指向档案或占位页 | `/substances`、`/substance/:id` |
| 只读索引 | `src/data/stepIndex.ts` | 把多份通路 JSON 归一成「pathwayId + stepId」查询结构 | 内容气泡、单步页 |
| 页面 | `src/pages/*` | 首页、通路挂图、单步、结构对照、物质/分子档案 | 路由 |
| 校验 | `tools/validate-*.mjs`、`tools/audit-layout.mjs`、`tools/smoke-*.mjs` | 结构校验、版式体检、真实浏览器断言 | 命令行 |
| 资产生成 | `scripts/*.mjs` | SVG、SDF、3D 配体等离线资产 | 构建前 |

> 口径修正：用户提到的 `scripts/validate-* / smoke-*` 实际位于生化的 **`tools/`**；`scripts/` 只放资产生成与截图脚本。新站沿用 `tools/` 这一约定更清楚。

### 1.2 数据层怎么被页面取用

生化的核心模式是「**点 = 实体，边 = 步骤**」：

- 通路 JSON 的 `entities[]` 只登记身份（id、名称、缩写、`metabolite` / `enzyme`）；
- `steps[]` 的 `substrates`、`products`、`enzyme.entityId`、`cofactors` 全部引用实体 id；
- `skeleton.json` 的 `nodes[]` 引用同一批实体 id，`links[]` 再用 `stepId` 把「相邻节点」和「一步反应」绑起来；
- 页面不自己写数组，导航、PLATE 编号、步数从 `homeMap.ts` 推导。

因此同一实体在挂图、单步、档案三处出现时，只有一份身份数据；差异只体现在「用哪些字段」。

### 1.3 挂图与档案页的关系

- 挂图页回答「这一步在整条链的哪里、上下游是谁」；
- 档案页回答「这个实体本身是什么、怎么工作、有什么边界」；
- 两者通过 **实体 id** 关联，不互相复制正文；
- 档案侧有一层别名归一（`canonicalMoleculeId` + `PROFILE_ALIAS_EXTRA`），解决「同一物质在挂图上多个节点 id」的问题；
- 档案页的正文是四段式：`position`（在链上的位置）→ `flow`（生成与去路）→ `significance`（生理/临床落点）→ `exam`（考点与易错），页头另有判断句 `claim`、`classification`、`aliases`、`structure`、`sources`。

### 1.4 校验脚本管什么

| 脚本 | 管的事 | 对新站的启示 |
|---|---|---|
| `validate-<pathway>.mjs` | 步骤齐全、实体 id 存在、分类分组、数值口径、幽灵引用、骨架几何 | 每类实体/每组关系都要有机械校验 |
| `validate-molecule-notes.mjs` | 档案全覆盖、六段非空、条目数区间、气泡字数、禁用字段、禁用「页码/真题年份」 | 档案页也要有硬门槛，防止写成散文 |
| `validate-substances.mjs` | 目录条目与档案/占位页的链接存在性 | 索引页不得出现幽灵链接 |
| `audit-layout.mjs` | 裁切、横向溢出、文本重叠、图框、完整性 | 总图与档案页都要过版式体检 |
| `smoke-*.mjs` | 真实浏览器断言：节点数、边数、点击语义、URL 还原、无控制台错误 | 总图交互必须可回归 |

校验分三层：**结构 → 版面 → 浏览器行为**，且全部是独立脚本，不塞进 `vite build`。

### 1.5 可直接复用的四条原则

1. **单一内容源**：同一实体只维护一份身份数据，页面不复制段落。
2. **事实与版面分离**：JSON 存内容与关系，坐标存 `map.json` / `layout.ts`。
3. **可选字段 + 缺省隐藏**：没有证据的字段不填，页面按「有则显示」处理。
4. **机械可判定的事交给脚本**：id 存在性、字段完整、幽灵链接、版式溢出，不靠人眼。

## 2. 基因工程的数据分层

### 2.1 六层模型

| 层 | 目录（建议） | 职责 | 不做什么 |
|---|---|---|---|
| L0 原始笔记 | `notes/`（只读） | 事实底稿、页码定位、疑点清单 | 不直接进站点 |
| L1 实体层 | `src/data/knowledge/entities/<category>/<id>.json` | 身份、别名、一句话定位、分类型参数、出处、状态 | 不写四段长文 |
| L2 关系层 | `src/data/knowledge/relations.json` | 实体与实体、实体与操作之间的有向关系 | 不存坐标 |
| L3 图谱层 | `src/data/knowledge/map.json` | 节点、边、泳道、坐标、可视类型、路线归属 | 不存正文 |
| L4 档案层 | `src/data/knowledge/profiles/<category>/<id>.json` | 四段式档案正文、对比、边界、关联 | 不重复实体参数 |
| L5 索引层 | `src/data/knowledge/taxonomy.json` + 运行时派生 | 六类目录、A–Z、按站筛选、搜索 | 不手写第二份清单 |

> 与生化的对应：L1+L2 相当于通路 JSON 的 `entities` 与步骤关系；L3 相当于 `skeleton.json` + `homeMap`；L4 相当于 `moleculeProfiles.ts`；L5 相当于 `substances.ts`。
> 与生化的差异：生化以「通路」为组织单位，新站以「实体 + 操作图」为组织单位，**没有章节正文层**。

### 2.2 实体六类与字段

所有实体共享一组「身份字段」：

```jsonc
{
  "id": "enz-ecori",              // 全局唯一，前缀标类别
  "category": "enzyme",           // enzyme | vector | technique | host | part | concept
  "name": "EcoR I",
  "en": "EcoRI",
  "aliases": ["EcoRⅠ"],
  "summary": "识别 GAATTC 的 II 型限制酶，切后产生 5′ 黏性末端。",
  "spec": { },                    // 分类型参数，见下表
  "sources": [
    { "note": "ch02-工具酶.md", "locator": "pp.3–24" }
  ],
  "status": "ready",              // ready | pending
  "pendingNote": null
}
```

六类的 `spec` 字段建议：

| 类别 | 前缀 | `spec` 字段 | 说明 |
|---|---|---|---|
| 工具酶 | `enz-` | `ecNumber`、`recognitionSite`、`cutPattern`、`ends`（黏性/平齐/切口）、`isoschizomers`、`methylationSensitive`、`starActivity`、`conditions`（缓冲液/温度）、`inhibitors`、`applications[]`、`subtype`（I/II/III/IV 或聚合酶/连接酶等） | 识别序列、末端类型、星活性是重点 |
| 载体 | `vec-` | `vectorType`（克隆/表达/穿梭/整合/人工染色体）、`capacity`、`copyNumber`、`incompatibilityGroup`、`markers[]`、`mcs`、`promoter`、`hostRange`、`size`、`transferable`、`examples[]` | 容量与标记基因必须带口径说明 |
| 技术 | `tec-` | `stage`（切/接/转/检/养）、`principle`、`steps[]`、`materials[]`、`readout`、`sensitivity`、`limits[]`、`variants[]` | 方法步骤只写「做什么」，不写实验课操作细节 |
| 宿主 | `host-` | `kingdom`（原核/真核）、`genotypeTraits[]`、`advantages[]`、`limitations[]`、`compatibleVectors[]`、`transformationMethods[]`、`expressionSystem`、`safetyNote` | 宿主缺陷型、密码子偏好、蛋白酶缺陷 |
| 元件 | `part-` | `partType`（启动子/RBS/终止子/标记基因/报告基因/MCS/标签/复制子/信号肽）、`function`、`position`、`strength`、`inducible`、`hostScope`、`examples[]` | 元件是「挂在载体或表达盒上的零件」 |
| 概念 | `con-` | `definition`、`scope`、`misconceptions[]`、`relatedConcepts[]`、`boundary`（安全/法规/伦理） | 只收笔记中出现的概念，不做百科扩写 |

补充约定：

- `summary` 一行，用于图上气泡与索引卡；不超过 40 个汉字。
- `sources.locator` 写笔记文件名 + 页码范围；**不写教材页码、不写真题年份**。
- `status: "pending"` 只用于「笔记明确存在矛盾/缺口」的条目，`pendingNote` 必须写清缺什么，不写猜测结论。
- 同一实体只允许一个 `id`；挂图上的变体 id 通过 `aliases` 或独立的 `mapAlias` 字段归一，不复制实体。

### 2.3 关系类型

关系独立于图谱存在，图谱只是关系的一种可视投影。

| 类型 | 语义 | 典型例子 | 方向 |
|---|---|---|---|
| `uses` | 操作使用某工具/载体/宿主/技术 | 酶切 → 限制性内切酶 | 操作 → 实体 |
| `catalyzes` | 酶催化某操作 | EcoR I → 酶切 | 酶 → 操作 |
| `recognizes` | 酶识别某序列/结构 | EcoR I → GAATTC | 酶 → 序列/元件 |
| `belongsTo` | 实体属于某类 | pBR322 → 质粒载体 | 子 → 类 |
| `dependsOn` | 操作/技术依赖前置条件 | 连接 → 酶切 | 后 → 前 |
| `contrastsWith` | 易混对比 | 克隆载体 ↔ 表达载体 | 双向 |
| `selects` | 标记/方法筛出目标 | 抗性基因 → 抗性筛选 | 元件 → 判定点 |
| `verifies` | 技术验证某步结果 | 酶切鉴定 → 重组子 | 技术 → 判定点 |
| `carries` | 载体运载片段 | 表达载体 → 目的基因 | 载体 → 元件 |
| `expresses` | 宿主/载体表达产物 | pET → 目标蛋白 | 载体/宿主 → 产物 |
| `constrains` | 安全/法规约束操作 | 生物安全准则 → 导入 | 概念 → 操作 |
| `alternativeTo` | 同类替代方法 | 化学合成 ↔ 基因组文库 | 双向 |

```jsonc
{
  "id": "rel-ecori-cut",
  "type": "catalyzes",
  "from": "enz-ecori",
  "to": "op-cut",
  "label": "在位点处切开双链",
  "note": null,
  "source": { "note": "ch02-工具酶.md", "locator": "pp.3–24" },
  "status": "ready"
}
```

约束：

- `from` / `to` 必须能在 L1 实体或 L3 操作节点中找到；
- `contrastsWith` 与 `alternativeTo` 必须成对出现（校验器检查对称性）；
- 一条关系只表达一个语义，不写「既使用又催化」的复合边；
- 笔记中没有明确依据的关系不建，不靠常识补。

### 2.4 与生化模型的差异

| 生化 | 新站 | 原因 |
|---|---|---|
| 通路 = 一条代谢链 | 操作图 = 一条实验链路 | 基因工程不是代谢流，没有化学计量 |
| `Step.substrates/products` 是代谢物 id | `Operation.inputs/outputs` 是材料/中间产物 | 输入输出是 DNA 片段、载体、宿主，不是分子 |
| 器官维度 `organDiffs` | 无器官维度 | 笔记没有肝/肌/红细胞式差异 |
| `deltaG`、`ecNumber` 必填 | `ecNumber` 可选，无 `deltaG` | 笔记只对部分酶给 EC 编号 |
| 3D 结构资产 | 首期不做 3D | 笔记没有 PDB/结构资产 |
| 章节 → tour 只是入口 | 不设章节页 | 知识站不是课程，章节只作为来源定位 |

## 3. 「一张总图」怎么表达

### 3.1 主线与带

```text
┌──────────────────── 顶带：学科前史与总概念 ────────────────────┐
│  基因工程定义 · 三大发现 · 三大发明 · 上游/下游                  │
└───────────────────────────────────────────────────────────────┘

  元件架（供给）        主链（操作流）
  工具酶 ─┐
  载体   ─┼──→  ① 切  ──→  ② 接  ──→  ③ 转  ──→  ④ 检  ──→  ⑤ 养
  元件   ─┤        │          │          │          │          │
  宿主   ─┘        └──────────┴──────────┴──────────┘          │
                       失败回流：重切 / 重接 / 重转              │
                                                               ↓
┌──────────────────── 底带：边界与产出 ──────────────────────────┐
│  安全评价 · 法规管理 · 应用（医药/农业/工业）                    │
└───────────────────────────────────────────────────────────────┘
```

- 横向五条泳道对应五站，每站一条浅色带，顶部大号等宽编号 01–05。
- 左侧元件架是「供给区」，实体锚点挂在架上，用 `supply` 边指向使用它的操作。
- 顶带只放概念节点，不与主链抢视觉层级。
- 底带放安全/法规概念与产出应用，用 `constrain` 边回指操作。
- 失败回流只画三条：`检 → 切`、`检 → 接`、`检 → 转`；不画「养 → 切」这类笔记没有依据的回流。

### 3.2 节点类型与「步骤 / 实体」的区分

| `kind` | 含义 | 视觉 | 是否可点进档案 |
|---|---|---|---|
| `operation` | 主链操作站或子操作 | 实心圆环 + 等宽编号 | 否（进「操作说明」浮层或档案式操作页） |
| `gate` | 判定点（有无转化子、是否重组、序列是否正确） | 菱形 | 否（浮层给判据） |
| `entity` | 工具酶/载体/技术/宿主/元件锚点 | 小圆点 + 标签 + 引线 | 是 |
| `concept` | 概念/边界 | 空心点 + 「概念」角标 | 是（概念档案） |

关键规则：**操作站是流程节点，实体是知识节点**。

- 主链只放 `operation` 与 `gate`，保证一条线读得通；
- 实体不挤进主链，挂在泳道上下缘或左侧元件架；
- 同一实体只画一次，跨站使用时用 `supply` 边连到多个操作，不复制节点；
- 子操作（如「目的基因获取」）用 `level: "sub"` 挂在所属主站的上方，不另开泳道。

### 3.4 第一批节点量级

### 6.5 校验脚本分工

| 脚本 | 断言 |
|---|---|
| `validate-entities.mjs` | id 唯一、类别合法、必填字段非空、`spec` 字段属于该类白名单、`sources` 至少 1 条、`pending` 必须有 `pendingNote` |

构建约定：

- `npm run build` = `tsc --noEmit` + `vite build`，不把校验塞进构建；
- `npm run validate` = 四个结构校验依次执行；
- `npm run audit` / `npm run smoke` 在 `preview` 之后单独跑；
- 任何一批内容落地后，先跑该批的 `validate-entities` / `validate-profiles`，全量回归留到一批结束时统一跑。
